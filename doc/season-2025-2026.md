# 2025–2026 赛季

赛季定义、筛选与排序实现位于 `core.seasons`；在线加载通过同属 `core` 的 `RankLandClient`，结果再交给 `rating` 计算。

## 范围

赛季名称为 `2025-2026`，候选比赛严格来自 RankLand official collection 的：

- `icpc2025`
- `ccpc2025`

两个 collection 合并后再筛选。区域赛明确保留；网络赛、总决赛等其他非邀请赛也默认保留。已确认 `ccpc2025ladies`（第十一届中国大学生程序设计竞赛（女生专场））不纳入该综合系列，通过 `SEASON_2025_2026.exclude_ids` 在 Rating 计算前显式排除。

## 邀请赛与覆盖规则

默认排除标题规范化后包含“邀请赛”或 `invitational` 的比赛。若未来 RankLand 提供结构化比赛类型，应优先扩展为结构化判断。

`SeasonSpec.include_ids` 与 `exclude_ids` 提供显式覆盖：exclude 优先于 include，include 可保留标题看似邀请赛但经人工确认应纳入的比赛。每个候选比赛产生 `SeasonDecision`，记录是否纳入及原因。

## 排序

`startAt` 转换为 `Asia/Shanghai`：

1. 主键为上海本地日期；
2. 同日 CCPC 在 ICPC 前，不比较两者的具体开始时刻；
3. 同系列同日再按开始时间、规范化标题、contest UK 稳定排序；
4. 无时区的 `startAt` 按上海本地时间解释。

## 刷新检查

线上刷新后应审查：

- `icpc2025`、`ccpc2025` 是否均可定位；
- 每场比赛的纳入/排除原因；
- 区域赛是否完整；
- 标题未写邀请赛但实际为邀请性质的例外；
- 同日比赛是否按 CCPC → ICPC 排列。

确认过的例外应写为显式 ID override，而不是不断扩大模糊标题关键词。

## API 与测试

- `SEASON_2025_2026`
- `select_season`
- `load_2025_2026_season`

静态站点在桌面端分别显示并冻结排名与参赛者/学校；表格容器小于 `600px` 时把最终排名以 `#x 学校` 的形式放入学校副行，只冻结宽度为 `clamp(150px, 42cqw, 176px)` 的参赛者复合身份列。单场参赛表同样把比赛排名放在学校前并合入参赛者身份列，Rating 与变化列继续横向滚动。

测试覆盖邀请赛排除、区域赛保留、显式覆盖、同日 CCPC 优先、时区、完整 rating 集成路径和移动端单列冻结规则。
