# CCPCF 名额盘点

2026–2027 系列增加 `?series=2026-2027&view=ccpcf`，沿用 [WF / ECF 盘点](qualification-tracker.md) 的导航、配色、搜索、固定表头和移动端表内滚动。免责声明仍为“民间数据，仅供参考，不代表官方结果”。名额属于学校，表内队伍是成绩依据，不代表最终报名队伍。

## 规则与版本

用户指定的[名额分配规则](https://ccpc.io/rules/369)标题为“2025名额分配规则”，发布于 2025-07-30，正文适用 2025–2026 赛季。2026-11-17 核对该正文及官网规则目录，目录仍列这份名额规则；未取得新版。当前用用户指定规则推演 2026–2027，来源版本保留在本文及快照元数据，不声称组委会已确认沿用。按用户要求，页面移除规则版本与学校名额的整句提示，仅在底部名额类别旁提供官方规则链接。

本页仅分配全国赛成绩渠道：合并有相同参赛成员的队伍，取最好站内排名；每校第一队组成独立排名，前 100 名含并列获学校第一名额；每校第二队另排，前 20 名含并列再获第二名额。弃权后两渠道分别最多顺延 10 / 5 个名次；没有弃权输入，当前不模拟顺延。

女生、高职专场各最多 5 个限制队别的名额，弃权时最多顺延 3 校；未从成绩渠道取得名额的当学年相关承办校可得 1 个奖励名额；港澳台及海外参赛校每校最多 2 个。这四种渠道属于本页盘点范围外，在底部名称后标“（本页不包含）”，没有将上限累加成固定总名额。女生赛已赛，不冒称待赛。缺少女生／高职榜单的独立固定输入、承办奖励资格、地区资格与实际报名审核，不据学校名称猜测特殊资格。

## 身份、合并与排名

学校及成员分别用 `DefaultNormalizer`、`config/school-aliases.json` 规范化。CCPCF 的 `team.key` 是比赛 ID 与本地队伍 ID 的 SHA-256，仅标识一条成绩记录；增加 `memberKeys` 保存规范化成员名。展示名仍保留原样。不发布账号、逐题记录或队伍 token。

纯函数 `buildCcpcfQualification` 位于 `static/js/ccpcf-qualification.mjs`。按“规范学校 + 规范成员名”用并查集合并，连通关系传递：A 与 B 重叠、B 与 C 重叠，则三者一组；不只比较相同三人名单。不同学校的同名成员不合并。这是缺少可靠成员 ID 时的确定性假设；同校同名、转学、名单错误仍需官方核实。

每个合并组取最小正排名。每校组按最好名次、稳定键排序，前两组各进入一条渠道；同校最好名次相同的组用稳定键仅选展示代表，不改变学校所得名额数。渠道排名是 `1 + 严格更好名次的学校数`，采用 1、1、3 的竞赛排名，边界并列全纳入。不能按固定前 N 条截断，也不能将各站原始名次直接与 100 / 20 比较。

每个入选合并组只在最好名次的一次出现上标名额，其余出现标“重复”，灰色图例同步使用“重复”；非入选组仍标“未出线”。CCPCF 灰格表示同一合并组的其他成绩记录，不表示达到校内上限，因此不使用 ECF 的“重复 / 达上限”标签。成员合并和名额判定不变。搜索覆盖本组各次出现的队名与成员，能通过换人前后的姓名定位最好成绩。所有计算不修改输入。

## 厦门前瞻与名额危险度

各站共用前瞻配色。表格上方的图例用淡紫色表示“前瞻排名”，较深的紫色表示“预计出线”。

厦门列列出 11 月 19 日前瞻的 300 支正式队，默认按综合战力排名。表格上方的“前瞻排名指标”按钮组默认选中综合战力，也可点击 XCPC Rating、XCPC Elo、本赛季 Rating 或网络赛排名。多个待赛站已有前瞻时，仅显示它们共同计入综合战力的单项指标，一次切换会按同一指标在各站内部独立排名。全部待赛站均有前瞻时，合并各站预测成绩标记预计出线的代表队。仅余一站且已有前瞻时，启用下述逐队危险度判定；多站待赛时沿用未知赛站的占位压力估计。各项沿用前瞻页的正式队排名和并列规则，单项缺失的队伍列在末尾，没有该项名次。切换时保留表格的横向与纵向滚动位置、显示范围和当前搜索匹配队伍，按所选名次重新推演两条渠道、厦门预计出线标签和前三站危险度。模拟四站结果后，若厦门成绩是某校入围渠道的代表成绩，该队以紫色显示，右上角从左到右为“预计出线”“前瞻排名”两个标签。其余队伍使用更淡的紫色，只显示“前瞻排名”。悬停标签可分别查看预计取得的学校名额渠道和具体前瞻名次。同组多站同名次时沿用较早站的代表成绩，渠道边界并列均计入。按综合战力预计出线共 23 队，其中第一名额 13 队、第二名额 10 队。无评分队伍的排名提示为“前瞻无排名”。校名、队名、成员可搜索。[厦门前瞻来源](season-2026-2027-preview.md#2026-11-19-厦门站前瞻)

前三站入围代表格的颜色跟踪具体队伍。绿色挂“确定出线”，表示该队在厦门所有逐名次排列中都能通过第一或第二渠道。黄色和红色均挂“待定出线”：黄色表示按前瞻本队入围，但存在出局顺序；红色表示按前瞻本队已经被挤出。同校其他独立队可以反超；原队落到校内第二时按第二渠道重新比较，落到第三就失去代表位置。同一成员组合在厦门改名或提高成绩时继续跟踪。若厦门名单把两个此前独立的组连成一个，则以合并后最佳历史成绩归属一支历史代表，跨站同名次沿用较早成绩。粗框与格内的“第 1 / 2 名额”仍描述前三站当前位置。

最坏情形按用户选定的常规逐名次排列枚举，允许没有有效成绩；前瞻快照保留已知并列，渠道边界始终含并列。给定原队可达到的最终最佳名次 r，逐一核查同校顺位：若两支独立队能排在前面，原队可能出局。若恰有零或一支领先，分别检查第一或第二渠道。跨站相同名次沿用校内稳定键；同校超越者若须占厦门前 r−1 名，须从外校可用位置中扣除。自身成绩提高或同校对手追平须占据厦门第 r 位时，还须有足够的其他参赛队填满前 r−1 位。校外每所学校达到严格领先所需的不同厦门组数为 0、1 或 2；优先分配给所需位置少的学校，算出该情形下最多能领先的学校数。算法检查本队原有最好名次，以及本队在厦门可能取得的每个更好名次，因为换渠道后全国竞争对手也会变化。

| 综合战力预测下的前三站渠道 | 确定出线（绿） | 待定出线（黄） | 待定出线（红） | 当前站内边界 |
| --- | ---: | ---: | ---: | ---: |
| 第一渠道（101 队，含边界并列） | 14 | 80 | 7 | 92 |
| 第二渠道（20 队） | 2 | 8 | 10 | 33 |

例如浙江大学“猫没有通过图灵测试”以站内第 6 名暂列校内第二；按厦门综合战力前瞻，同校“队线大冲浪”取得第 5 名，“至亮之焰+”已有第 1 名，原队退到校内第三，标红。若名单或官方身份认定改变，需重新核查。

兼容没有前瞻的旧快照。名单未知时沿用未赛站数乘以 r−1 的保守上界及原有占位压力提示；第二名额另考虑未来名单的桥接风险。全部赛站结束后使用实际成绩。

## 页面和数据契约

复用 `renderQualification` 展示四站，行是各站成绩顺序，格内补充本站名次与合并后最佳名次，已选代表右上角显示“第 1 / 2 名额”。默认显示最靠后的入选代表或区域边界及后三行（本快照 95 行），支持完整榜单、搜索上下循环、Enter / Shift+Enter、清空恢复与零结果。刷新、返回、切换赛季、异步加载保护与其他盘点一致，两种快照分别缓存。

两个渠道分别绘制出线区域：深蓝实线框表示第一名额，紫色虚线框表示第二名额，并提供对应图例。每个渠道以入选学校的最差最佳站内名次 `cutoffRank` 为边界；已赛列包含本站排名不大于该值的全部记录，保留边界并列，厦门列按同一边界包含前瞻排名达线的队伍；缺少前瞻的待赛列保留对应空位。`channel.regionRows` 保存每列区域高度，纯函数 `ccpcfRegionEdges` 只绘制外轮廓，兼容列间高度不同、空列和没有入选学校的情况。两框独立计算，不假设第一名额区域必定更大；边界允许重叠，虚线直接覆盖实线，间隙露出实线。框内可能包含重复队伍、其他渠道队伍和待赛空位，不表示每格都获得对应名额。边框使用不拦截鼠标的伪元素，不改变单元格尺寸、搜索定位和出线计算。

本页不展示 WF / ECF 的“可选队伍”、承办前十标记、香港第二轮或 EC Final 列。页底六种名额逐项分行，只给类别、数量／含并列的排名范围及一句介绍，范围外四类另标“（本页不包含）”；不显示当前学校数、边界名次或“待核验”等补充文案。工具栏空搜索时仅显示行数，保留搜索结果计数。规则链接移至“名额类别”标题旁，免责声明之后直接展示图例。完整渠道限制保留在本文。共用承办标签在极窄格内允许收缩省略，完整文字与 title 保留，修复 1024px 回归发现的溢出。

schema v1 在共享字段 `seriesId/asOf/disclaimer/rules/stations` 外使用 `kind: "ccpcf"`、`firstQuota/secondQuota`、`ruleSeason/ruleNotice`；后两者仅保留为来源元数据，页面不渲染提示句；每条成绩增加 `memberKeys`。不伪造 ECF 配额字段。CCPCF 待赛站没有 `estimatedCount`，有成绩站的 count 校验与身份校验沿用共享加载器；rank=0 仅允许零题记录。入口校验拒绝重复路径；加载器验证赛季和模式。

待赛站可配置 `previewId`。离线生成时从对应的已提交前瞻提取正式队，在 `previewIdentities` 按队伍 ID 保存规范化的学校及成员键。页面通过 ID 关联同一赛季的前瞻；待赛站实际成绩数组 `teams` 仍为空。进入已赛状态后只使用正式结果。

显式离线重建，仅更新 CCPCF 快照及索引入口：

```bash
python -m scripts.generate_qualification_data --config config/ccpcf-qualification-2026-2027.json --input-dir data-cache/results-20261108-rankland --input-dir data-cache/results-20261115-rankland
```

新检出需按复盘中的来源 URL 准备固定哈希的 SRK；默认离线测试不需要缓存。通用 `scripts.generate_static_data` 仅复制提交的快照、登记入口，不重算或联网。公共 Python 包 API 与导出不变。
